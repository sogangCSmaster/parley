# Gemini real-time caption pipeline measurements (2026-10-16)

Tool: [bench/gemini](../../bench/gemini). Environment: Seoul, Gemini API **free tier** key, macOS TTS audio (Yuna, Kyoko).

## Summary

| Item | Result | Verdict |
|---|---|---|
| STT first interim result | ko 0.73s · ja 1.16s after audio starts | Good |
| STT interim cadence | **~0.49s** (p90 0.53s) | Good — captions keep up with speech |
| STT lag (speech → interim) | ~0.5–0.7s | Good |
| STT end of speech → final | ko 1.34s · ja 0.12s | Good |
| Translation (Flash-Lite) first token | **p50 2.49s · p90 3.84s · max 10.4s** | **Over target (1.5s)** |
| Translation output speed | total − first token ≈ 0.1s | Fast once it starts |
| Thinking tokens | 0 (`thinkingLevel: minimal`) | Thinking off works |
| Free-tier errors | 4 of 38 calls failed (503 overloaded, 429 quota) | Not usable for a real service |
| Network round-trip | Connect 40ms, TLS 85ms | **Network isn't the bottleneck** |
| Translation cost | ~97 input tokens, ~19 output tokens per call → **$0.000076/call** | Very cheap (projected $0.003/min at 40 calls/min) |

## Conclusion

- **STT (`gemini-3.5-transcribe-live`) fits the requirements as-is.** It sends the full text so far every 0.5s, so "captions that follow while you speak" works right away.
- **Translation latency is the only blocker.**
  - Network is ~40ms and output is ~0.1s, so almost all of the ~2.4s is model wait time on the free tier.
  - The paid tier (and its Priority tier) still needs to be measured, which means enabling billing.
- Real cost per speaking minute ≈ STT $0.009 + translation $0.003 ≈ **$0.012/min**. That's half of the earlier $0.025 estimate.

## Facts that affect the design

1. **Interim results are cumulative within a segment, and reset when a final arrives.** A final is cut at a pause, not at a sentence end; one Japanese final ended mid-sentence at "主にAI".
   → For each speaker, keep "final segments not yet ending a sentence + the current interim" stitched into one sentence buffer, and translate that buffer. Lock a sentence's translation only once the sentence-ending punctuation (。.?!) arrives.
2. **Japanese interims have spaces between words** ("私たち の 投資"); finals have none. → Remove spaces between CJK characters before displaying or translating.
3. An interim often comes back with no change from the previous one. → Only translate when the text has changed.
4. Recognition error example: TTS audio "注力しています" was recognized as "よく知っています". → Test with real voices, and consider adding meeting-specific terms with `customVocabulary`.
5. `gemini-2.5-flash-lite` can no longer be used by new users (404). `gemini-3.6-flash` was hard to measure on the free tier (9 successes, p50 1.4s).

## Re-measurement (same day, paid tier attempt)

- In 3 runs of 57 calls, 29 failed with `429 You exceeded your current quota`, so this was still the free tier. Latency of successful calls was the same: first token p50 2.47s, p90 3.85s.
- The response header `x-gemini-service-tier` was not present (`-`).
- The tool now has a `--service-tier standard|priority|flex` option and records the tier that actually handled each call. Priority is only available to Tier 2–3 paid accounts, and requests over the limit are downgraded to Standard.
- **Next**: rerun `cargo run --release -- translate --runs 3` (and `--service-tier priority`) once billing is on.

## Paid tier (prepaid credit added, same day)

| Run | Calls (errors) | First token p50 | p90 | max | Notes |
|---|---|---|---|---|---|
| Free tier (earlier) | 38 (4) | 2.49s | 3.84s | 10.4s | Frequent 503/429 |
| Paid Standard | 57 (2) | **1.03s** | 1.63s | 21.2s | 2 errors were 402 right after adding credit (propagation lag). One 21s outlier |
| Paid, `--service-tier priority` requested | 57 (0) | **0.95s** | 1.21s | 1.94s | **Actually processed as Standard** (response header `x-gemini-service-tier: standard`) |

- Priority is only available to Tier 2–3 accounts. This account is Tier 1, so the request goes through but gets downgraded to Standard. The difference between the two rows is ordinary Standard variance.
- The streaming (SSE) response did not include the `x-gemini-service-tier` header; only the non-streaming response did. To check the tier, use one non-streaming call.
- **Paid Standard is enough**: first token about 1.0s (p50), mostly within 1.2–1.6s (p90). Going from free to paid alone cut latency by more than half.
- **The remaining risk is a rare long tail** (21s in one of 57 calls). If a request has no first token within 1.5s, fire the same request once more and use whichever answers first (hedging). The extra cost is negligible because the prompt is small (~$0.00008 per call).

### Expected end-to-end latency (paid Standard)

- While speaking: STT interim ~0.5–0.7s behind speech + translation first token ~1.0s → the translated caption trails speech by about **1.5–1.7s**.
- After speech ends: STT final 0.1–1.3s + translation ~1.0s. But the partial translation of the nearly finished sentence is already on screen, so the final translation is only a correction.
- Cost: STT $0.009 + translation $0.003 ≈ **$0.012 per speaking minute** (unchanged).

### Decisions

1. Use paid Standard + `gemini-3.5-flash-lite` + `thinkingLevel: minimal`.
2. Hedge translation requests (resend once if no first token within 1.5s) and use latest-wins cancellation (when newer text arrives, cancel the in-flight request).
3. Priority: re-check when the account reaches Tier 2 (only a request-field change).

## Skipping silence (`gemini-bench gap`)

Scenario: utterance 1 → silence where **no audio at all is sent** → utterance 2. Paid Standard.

| Mode | Silence | Result |
|---|---|---|
| auto (server VAD), 600ms of trailing silence then stop | 20s | Session held, but **no final for either utterance**. Utterance 2 got appended to utterance 1's turn |
| manual (`activityStart`/`activityEnd`) | 20s | Both finals arrived normally, **0.42s / 0.31s after activityEnd**. Korean → Japanese language switch detected automatically |
| auto, nothing sent | 660s | **Session closed 60s after the last input** (`The operation was aborted.`, no goAway) |
| manual, nothing sent | 75s | Also **closed 60s after the last input** |
| manual + keepalive (100ms of silence every 30s) | 75s | Session held, utterance 2 recognized normally (finals 0.39s / 0.33s), audio sent was **25%** of elapsed time |
| manual + keepalive | 660s | Closed **281s** in (about 270s of silence, 9 keepalives sent) with `Deadline expired before operation could complete.`, no goAway. **Keepalive alone can't survive long silences** |

Conclusion: skip silence with **client VAD + manual activity signals + 30s keepalive**, and once silence passes 3 minutes, **rotate sessions** by opening a new one in the background ahead of time. With silence skipped, the amount of audio sent fell to 21–49% of elapsed time.
